# Spec: Real Data on Portal Screens (and Honest Labels for Demo Features)

- **Status:** Story approved by the owner on 2026-10-08. Technical brief pending (gate 5).
- **Order:** slice 2 of the remaining known-broken fixes. The owner set the order on 2026-10-07: rate limits (done, ADR 0026) → real portal data → applications → conference hub.
- **Branch:** `fix/real-portal-data`

## Problem

Research on `main` (2026-10-07) found screens that show invented data as if it were real.

**Institution home (`app/(institution)/institution/page.tsx`)**
- Hard-codes "Westminster Theological Seminary", "Glenside, PA", "ATS & MSCHE Accredited" and "Verified Academic Partner".
- Hard-codes the counts 3 sent, 2 awaiting, 1 accepted and 4 shortlisted, plus "Average response time: 48h".
- The real query functions `fetchInstitutionProfile` and `fetchInstitutionStats` exist but are never called.

**Institution shortlist (`app/(institution)/institution/saved/page.tsx`)**
- Seeded with fake scholars and courses (`f1000000-…`, `c1000000-…`). Real data is never loaded.
- **Bug:** "Remove" POSTs the fake IDs to a *toggle* API, so removing a real item could instead *add* it.

**Scholar dashboard (`app/dashboard/page.tsx`)**
- Hard-codes the initials "SC", "Live Revision #1 / Draft Revision #2", "Approved & Active", 4 inquiries, "+2 this month", 182 views, "+18%", 3 syllabi and the availability text.

**Scholar inquiry inbox (`components/inquiries/scholar-inquiry-inbox.tsx`)**
- Renders the hard-coded `DEFAULT_INQUIRIES`.

**Analytics (`/dashboard/analytics`)**
- Every number is generated by a formula (for example `182 + publications*25`).
- The page shows a "Live Feed" badge over that synthetic data.
- No view or impression data is collected anywhere.

**Conference hub (`/institution/conferences`)**
- Uses in-memory demo data, with a hard-coded institution ID.
- Shows "Saved to Committee Docket" although nothing is saved.
- Pre-fills unscored candidates as 5/4/5 "strong_hire".
- The public scholar profile shows hard-coded conference appearances for demo slugs.

## Story

As a **scholar** or an **institution user**, every number, list and status I see in my portal is real and mine. Anything that is not built yet is clearly labelled as a preview or as sample data, so I am never misled.

### Acceptance criteria

#### A. Institution home
1. The name, location, accreditation and verification badge come from the signed-in user's own institution. Membership is resolved from the session; a client-supplied id is never trusted.
2. The counts (inquiries sent, awaiting response, accepted, shortlisted) are real queries scoped to that institution under RLS.
3. "Average response time" is **removed**, because it is not tracked reliably.

#### B. Institution shortlist
4. Saved scholars and saved courses load from the database for the user's institution, under RLS. Each shows the fields the cards need.
5. Remove is an explicit delete that can never add an item. The list updates on success, and a failure shows a clear error.
6. Empty states are honest ("No saved scholars yet").

#### C. Scholar dashboard and inbox
7. The scholar dashboard shows real values, all scoped to the session scholar:
   - initials and name;
   - profile status (draft, under review, published or hidden);
   - revision status (from ADR 0024);
   - inquiry count and month-over-month change, computed from `inquiries.created_at`;
   - published course count;
   - availability.
8. Directory views and "+18%" are removed, because no view data exists.
9. The inquiry inbox lists the scholar's real inquiries, reusing the existing scholar inquiry query, and keeps the existing accept/decline actions.

#### D. Analytics: honest labelling (owner decision)
10. `/dashboard/analytics` stays visible but is clearly marked **"Sample data — analytics are coming soon"**.
    - The marking is a prominent banner, not small print.
    - The "Live Feed" badge is removed.
    - Every metric reads as illustrative.

#### E. Conference hub: preview label and hidden (owner decision)
11. `/institution/conferences` is shown only to platform staff (admins), and is labelled **"Preview — demo data, nothing is saved"**. Non-staff institution users don't see it in navigation, and reaching it directly shows a short "coming soon" notice.
12. The false "Saved to Committee Docket" message is removed.
13. Rubric scores start unset; there is no default "strong hire".
14. The hard-coded conference appearances on public scholar profiles are removed until the hub is built.

#### F. Tests and gates
15. Page-guard tests:
    - every changed page requires the right role;
    - the institution pages never accept a client-supplied institution id.
16. Unit tests for the stats and dashboard mappers, with real-role integration tests where a query is new:
    - an institution sees only its own counts;
    - a scholar sees only their own inquiries.
17. A regression test fails if the known fixture literals reappear in `app/` or `components/` ("Westminster Theological Seminary", "182", "Live Feed", `DEFAULT_SAVED_SCHOLARS`, `DEFAULT_INQUIRIES`).
18. The E2E journeys are updated:
    - the institution persona's real shortlist is shown;
    - remove works;
    - the scholar dashboard shows real status;
    - analytics shows the sample banner;
    - the conference page is hidden from the institution persona.

### Non-goals
- Real analytics or telemetry. That is a future feature and needs a privacy review.
- Building the conference hub, which comes after applications.
- Applications and the applicant matrix (slice 3).
- Redesigning any page beyond replacing fixture data.

## Owner decisions
1. The order (2026-10-07).
2. Analytics: label it as sample data (2026-10-07).
3. Conference hub: demo label and hidden from non-staff (2026-10-07).
4. Defaults proposed in this story:
   - drop "average response time";
   - remove directory views and their trend until telemetry exists;
   - the month-over-month inquiry change is computed from `created_at`.
