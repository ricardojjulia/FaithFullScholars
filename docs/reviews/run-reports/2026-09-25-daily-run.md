## 2. System Audit & Issue Discovery

1. **MVP Implementation Plan Status:**
   - Audited `docs/FAITHFULL_SCHOLARS_FULL_PLAN.md`. All phases (Phase 0 through Phase 13) are marked `[x]` complete.
   - Audited previous merges (PRs `#27` through `#32`), including internationalization dictionary coverage, distinguished scholar dossiers, institutional inquiry systems, and multi-tenant RLS isolation.
2. **Full System Verification & Test Race Condition Discovery:**
   - Ran `npm run verify` to test platform integrity.
   - Detected an intermittent assertion failure in `tests/integration/domain-rls.test.ts`:
     ```
     FAIL tests/integration/domain-rls.test.ts > Phase 1 Domain Foundation & RLS Integration Tests > 2. verifies approved scholars and published revision pointers (ADR 0005)
     AssertionError: expected null not to be null
     ```
   - **Root-Cause Analysis:**
     - Vitest executes test suites in parallel worker threads by default.
     - ADR 0005 dictates that approved scholars must link to a valid published profile revision (`published_revision_id IS NOT NULL`).
     - In `tests/integration/institution-inquiry.test.ts`, the test fixture `dr-inquiry-scholar` was inserted directly with `profile_status = 'approved'` without creating any revision or setting `published_revision_id`.
     - In `tests/integration/security-guardrails-and-rls.test.ts` and `tests/integration/admin-review.test.ts`, test scholars were inserted initially with `profile_status = 'approved'` before creating revisions and updating the pointer in subsequent queries.
     - Concurrently running `domain-rls.test.ts` queried `SELECT s.slug, s.profile_status, s.published_revision_id FROM public.scholars s WHERE s.profile_status = 'approved'` without scoping out ephemeral test fixtures, intermittently catching these unlinked test records mid-test.

## 3. Remediation & ADR 0005 Invariant Enforcement

To eliminate the race condition and strictly uphold ADR 0005 across all test suites, four test files and the project changelog were updated:

1. **`tests/integration/domain-rls.test.ts`**:
   - Added explicit exclusion filters to the baseline seed query (`s.slug NOT LIKE 'test-%' AND s.slug NOT LIKE 'dr-inquiry%' AND s.slug NOT LIKE 'admin-review%'`), isolating baseline seed assertions from concurrently running ephemeral test fixtures.
2. **`tests/integration/institution-inquiry.test.ts`**:
   - Seeded approved profile revision `testRevisionId` (`01888888-0000-0000-0000-000000000088`) and set `published_revision_id` for `dr-inquiry-scholar`, maintaining complete ADR 0005 revision fidelity.
   - Added clean teardown in `afterAll` setting `published_revision_id = NULL` and deleting the revision prior to scholar removal.
3. **`tests/integration/security-guardrails-and-rls.test.ts`**:
   - Seeded `test-guardrail-marcus-vance` initially with `profile_status = 'draft'`, then elevated status to `'approved'` and linked `published_revision_id` atomically in a single update.
4. **`tests/integration/admin-review.test.ts`**:
   - Seeded `admin-review-test-scholar` initially with `profile_status = 'draft'`, then elevated status to `'approved'` and linked `published_revision_id` atomically in a single update.
5. **`CHANGELOG.md`**:
   - Added a `### Fixed` entry under `## [Unreleased]` documenting the test concurrency and ADR 0005 fixture revision integrity resolution.
