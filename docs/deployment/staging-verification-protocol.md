# FaithFull Scholars — Remote Staging & Production Verification Protocol

> **Specification & Roadmap:** [`docs/FAITHFULL_SCHOLARS_FULL_PLAN.md`](../FAITHFULL_SCHOLARS_FULL_PLAN.md) §18 (Phase 7 & 8)  
> **Deployment Architecture:** [`docs/deployment/vercel-supabase.md`](vercel-supabase.md) & [ADR 0004](../adr/0004-vercel-supabase-platform.md)  
> **Security Mandate:** 100% PostgreSQL Row Level Security (RLS) across all 28 tables prior to opening platform traffic.

---

## 1. Executive Summary & Purpose

This protocol defines the mandatory pre-flight verification sequence for deploying FaithFull Scholars to remote environments (Staging and Production). It ensures that database migrations, multi-tenant Row Level Security, pilot reference data, production edge headers, and Vercel edge runtimes are rigorously tested and signed off before admitting external pilot users.

---

## 2. Environment Architecture & Secrets Quarantine

### Required Remote Environment Variables

| Variable | Scope | Description | Security Classification |
|:---|:---|:---|:---|
| `NEXT_PUBLIC_SUPABASE_URL` | Client & Server | Project API URL (`https://<project-ref>.supabase.co`) | Public Safe |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Client & Server | Public PostgREST API key (RLS enforced) | Public Safe |
| `SUPABASE_SERVICE_ROLE_KEY` | Server Only | Privileged admin key for backend operations | **Strict Confidential** (Quarantine from client bundles) |
| `DATABASE_URL` | CI / Migrations / Audit | Transaction/Session pooler connection string | **Strict Confidential** |
| `GEMINI_API_KEY` | Server Only | Google AI Studio key for CV & syllabus intelligence | **Strict Confidential** |
| `NEXT_PUBLIC_PILOT_FEEDBACK_ENABLED` | Client & Server | Feature flag for feedback widget (`true` in pilot/staging) | Public Safe |

> [!CAUTION]
> **Secret Hygiene:** Never commit `.env.local` or environment secrets to Git. Never prefix `SUPABASE_SERVICE_ROLE_KEY` or `GEMINI_API_KEY` with `NEXT_PUBLIC_`. Confirm that client bundles generated by `npm run build` do not contain service-role strings.

## 3. Protocol Execution Runbook

### Step 1: Supabase CLI Project Link & Migration Synchronization

1. Authenticate with Supabase CLI:
   ```bash
   npx supabase login
   ```
2. Link the repository to the remote target project:
   ```bash
   npx supabase link --project-ref <your-remote-project-ref>
   ```
3. Inspect migration divergence:
   ```bash
   npx supabase migration list
   ```
4. Push pending migrations to the remote database:
   ```bash
   npx supabase db push
   ```
   *Expected Outcome:* All 4 baseline migration files (`00001_foundation.sql`, `00002_rls_and_institutions.sql`, `00003_courses_and_showcase.sql`, `00004_pilot_feedback_and_triage.sql`) are applied cleanly with zero errors.

### Step 4: Next.js Production Build & Security Header Validation

1. Execute the full local verification pipeline:
   ```bash
   npm run verify
   ```
   *Criteria:*
   - `version:check`: Semantic version alignment across `package.json`, `package-lock.json`, and `docs/`.
   - `lint`: 0 ESLint errors or warnings.
   - `typecheck`: 0 TypeScript compiler errors.
   - `test`: 25 test suites, 134 tests passing.
   - `audit:rls`: 28/28 tables verified.
   - `build`: Next.js Turbopack production bundle succeeds with 0 route errors.

2. Verify HTTP Security Headers in [`next.config.ts`](../../next.config.ts):
   - `Content-Security-Policy`: Scripts, styles, frames (YouTube), and images (Supabase Storage, Gravatar, Unsplash) strictly whitelisted.
   - `Strict-Transport-Security`: `max-age=63072000; includeSubDomains; preload`.
   - `X-Frame-Options`: `DENY`.
   - `X-Content-Type-Options`: `nosniff`.
   - `Referrer-Policy`: `strict-origin-when-cross-origin`.

## 4. Rollback & Incident Playbook

In the event of a critical security regression, migration failure, or authorization flaw during remote deployment:

1. **Immediate Traffic Halt:**
   - In Vercel Project Settings > Deployments, instantly rollback to the prior stable production deployment ID.
2. **Database Schema Rollback:**
   - If a newly applied migration caused data or RLS issues, revert the specific migration in a new rollback migration file and push via `supabase db push`.
3. **Quarantine & Root Cause Analysis:**
   - Log incident details in `docs/factory/` using the Daily Incident Protocol.
   - Re-run `DATABASE_URL=... npm run audit:rls` to verify data isolation before resuming traffic.
